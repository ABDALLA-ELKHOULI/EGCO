# نظام الملاحظات — كيف يعمل

الملاحظات تصل على دفعات أثناء الاستعمال، لا مرة واحدة. هذا طبيعي: تُكتشف الأمور
وأنت تشتغل على التطبيق فعلاً. المشكلة ليست التقسيط — بل أن الملاحظة تصل **أثناء
عمل جارٍ فتقاطعه**، فينتهي الأمر بأربعة أشياء نصف مبنية بدل واحد منتهٍ. وما لا
يُكتب يُنسى: الجلسة تنتهي، والذاكرة معها.

## القاعدة الأولى — الالتقاط قبل التنفيذ

أي ملاحظة تصل تُكتب فوراً في `INBOX.md` بنصّها كما قيلت، ثم يُكمَل العمل الجاري.
**لا يُقاطَع عملٌ جارٍ إلا لخللٍ في رقم** — رقم خاطئ على الشاشة يُصلَح فوراً لأن
قرارك يُبنى عليه.

## الملفات الثلاثة

| الملف | ماذا فيه |
|---|---|
| `INBOX.md` | ملاحظاتك بنصّها، بتاريخها — غير مصنّفة بعد |
| `BACKLOG.md` | مصنّفة ومرقّمة، بحالة كل واحدة |
| `SHIPPED.md` | ما أُغلق، في أي إصدار، وكيف تحقّقنا |

## الترقيم

`م-١`، `م-٢`… رقم لا يُعاد استعماله أبداً، حتى لو أُلغيت الملاحظة. تقول «م-٤٧ وين
وصلت؟» فيأتي الجواب في ثانية، وأي جلسة جديدة تعرف الحالة دون أن تشرح من أول.

## التصنيف — ثلاث خانات فقط

| النوع | المعنى | الأولوية |
|---|---|---|
| **خلل** | رقم غلط · ملف يُرفض · شاشة تنهار | يقفز الصف — يُصلَح ويُشحن وحده |
| **نقص** | ميزة ناقصة تعطّل العمل | دفعة الإصدار القادم |
| **تحسين** | شكل · ترتيب · راحة | تتراكم وتُشحن مجمّعة |

## الحالات

`جديدة` → `قيد العمل` → `منتهية` → `مشحونة` · أو `مؤجَّلة` / `ملغاة` (بسبب مكتوب).

«منتهية» تعني الكود جاهز ومختبَر. «مشحونة» تعني وصلت جهازك. الفرق مقصود:
الأولى مسؤوليتي، والثانية هي التي تلمسها أنت.

## بوابة الإغلاق

لا تُغلَق ملاحظة قبل:

1. اختبارات الخادم كلها ناجحة (`pytest`)
2. `npx tsc --noEmit` نظيف
3. **تحقُّق على بيانات حقيقية** — لا على مثال مصنوع
4. سطر في `SHIPPED.md` يقول **كيف** تحققنا، لا «تم» فقط

## الإصدار

كل إصدار = دفعة أرقام مغلقة، ورسالة الإصدار تذكرها صراحةً: «أغلق م-٤١، م-٤٤، م-٤٧».
فتعرف بالضبط ماذا وصلك، ونعرف بالضبط ماذا بقي.
